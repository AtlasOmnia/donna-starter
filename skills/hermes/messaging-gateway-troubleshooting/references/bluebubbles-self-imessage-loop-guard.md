# BlueBubbles self-iMessage loop guard

Context: When the user texts Hermes from the same Apple ID / iMessage identity that the BlueBubbles Mac is signed into, BlueBubbles may mark the inbound webhook message as `isFromMe=true`. A blunt guard that ignores all `isFromMe` messages prevents loops, but also prevents the owner from texting Hermes from their own iMessage identity.

Durable fix pattern:

1. Do not ignore every `isFromMe=true` webhook.
2. Track outbound message identifiers generated by Hermes:
 - `tempGuid` sent to BlueBubbles
 - returned `guid` / `messageGuid` from BlueBubbles send APIs
3. On inbound webhook, extract message identity from:
 - `guid`
 - `messageGuid`
 - `id`
 - `tempGuid`
 - `temp_guid`
4. Ignore `isFromMe=true` only when the inbound ID matches the outbound-ID cache.
5. Let other `isFromMe=true` messages continue through normal authorization/pairing, because they may be genuine owner-authored messages from the same iMessage account.

Verification loop used successfully:

- Add regression test: `isFromMe=true` self-authored DM with an unknown message ID is dispatched.
- Add regression test: `isFromMe=true` webhook with a known outbound message ID is ignored.
- Run targeted tests first, then the full BlueBubbles test module.

Operational setup reminders:

- BlueBubbles webhook should be listening locally, commonly `127.0.0.1:8645`.
- `curl http://127.0.0.1:8645/health` should return `ok`.
- Check BlueBubbles server's registered webhook list to verify Hermes registration.
- Prefer explicit IPv4 loopback in the registered BlueBubbles webhook URL: `http://127.0.0.1:8645/bluebubbles-webhook?...`.
- Avoid `http://localhost:8645/...` unless Hermes is also listening on IPv6. On macOS, BlueBubbles/Electron/Node can resolve `localhost` to `::1`, causing `connect ECONNREFUSED ::1:8645` even when the IPv4 health check passes.
- Remove stale BlueBubbles webhook registrations for old ports or `localhost` URLs before retesting; otherwise logs may show noisy failures against dead endpoints.
- After patch/config change, restart Hermes gateway and verify `hermes status` plus gateway logs.
