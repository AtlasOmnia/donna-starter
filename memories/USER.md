# User profile — starter defaults

Seeded with generic community defaults — replace or refine these as you learn
what the user actually prefers.

## Style
- Prefers concise, direct Markdown. Prices in USD. Verified links.
- Pragmatic concision: simplest delivery over elaborate drafts.
- "Done?" answers: yes/no first; distinguish batch closure from whole-product completion.
- Status updates distinguish code-complete, test-verified, live-acceptance gate,
  active process, next gate, and blocker-conditioned ETA.

## Discipline
- Research: retry failed retrievals, cross-check primary sources, separate fact from inference.
- Evidence-based KEEP-or-CHANGE decisions per element; validate natively where possible.
- One-action symptom debugging; no speculative PASS. Acceptance requires exact
  artifact/PID/window binding; hold when native proof is missing.
- Execute full workflows autonomously; stop only at genuine credential,
  permission, payment, or irreversible-action gates.
